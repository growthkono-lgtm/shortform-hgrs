# 소개서 조판 규격

`scripts/build-deck.ts` 로 만드는 16:9 소개서의 그리드와 장표 유형별 규칙.

**새 장을 만들거나 기존 장을 고치기 전에 이 문서를 먼저 본다.** 여기 없는
유형이 필요하면 유형을 여기 정의하고 나서 코드를 쓴다.

고치고 나면 반드시:

```bash
npm run deck          # HTML + PDF 생성
npm run deck:doctor   # 넘침·잘림·미로딩 검사 — 0건이어야 한다
```

---

## 왜 규격이 필요한가

2026-08-19~20 사이에 같은 사고가 세 번 났다.

- `.bc-ev` 가 `overflow:hidden` 이라 **월별 실적표가 통째로 잘렸다.** 화면에는
  위 한 장만 보여서 "들어가 있는데 안 보이는" 상태였다.
- 소재 실적표를 한 장 더 끼웠더니 **영상 캡처가 깎였다.**
- SNS 케이스에는 증빙 상한이 없어 트러스티푸드 장표가 **아래로 37mm 넘쳤다.**

원인은 하나다. `.page` 가 `overflow:hidden` 이라 **넘쳐도 화면이 멀쩡해 보인다.**
mm 를 눈대중으로 고치면 다음 장에서 또 터진다. 그래서 치수를 한 곳에 모으고,
유형마다 규칙을 정하고, 검사기가 숫자로 잡게 했다.

---

## 그리드

토큰은 `scripts/build-deck.ts` 의 `:root` 에 있다. **장표에서 mm 를 새로 쓰지
말고 이 변수를 쓴다.**

| 이름 | 값 | 뜻 |
|---|---|---|
| `--pg-w` / `--pg-h` | 338.67mm × 190.5mm | 페이지 (16:9 = 13.333in × 7.5in) |
| `--pad-t` / `--pad-x` / `--pad-b` | 15 / 16 / 12mm | 패딩 |
| `--safe-w` / `--safe-h` | 306.67 × 163.5mm | 안전영역 |
| `--head-h` | 32mm | 머리 밴드 (h2 26pt + 서브라인 15pt + 여백) |
| `--foot-h` | 8mm | 푸터 밴드 |
| **`--body-h`** | **123.5mm** | **본문 밴드 — 본문 요소는 이 높이를 넘지 않는다** |
| `--col` / `--gut` | 20.06mm / 6mm | 12칼럼 · 거터 |
| `--u` | 4mm | 세로 리듬 단위 |

### 유틸 클래스

```
.grid        12칼럼 그리드 (gap: --gut)
.grid.rows2  2행 균등
.c3 .c4 .c5 .c6 .c7 .c8 .c12   칼럼 스팬
.fit         max-height: var(--body-h)
```

### 넘칠 때 하는 일

**절대 `overflow:hidden` 으로 자르지 않는다.** 자르면 화면에서 안 보이고 인쇄에서
사라진다. 셋 중 하나를 한다.

1. 항목 수를 줄인다 (증빙 3장 → 1장)
2. 장을 나눈다 (28건 → 6개씩 5장)
3. 이미지를 `flex:1 1 0` + `object-fit:contain` 으로 **남은 높이에 맞춰 줄인다**

## 장표 유형

유형은 `slide()` 가 뼈대 클래스를 보고 자동 판정해 `data-layout` 으로 심는다
(`inferLayout`). 손으로 달지 않는다 — 새 장에서 빠뜨리기 때문이다. 예외는
`slide(body, { layout: "..." })`.

| 유형 | 판정 클래스 | 구성 | 정원 |
|---|---|---|---|
| `cover` | `.cover` | 다크·풀블리드. 좌 텍스트 / 우 미디어 2×2 | — |
| `part` | `.part` | 다크·중앙 3줄 (키커·제목·설명) | — |
| `statement` | `.stmt` | 텍스트만. 키커 + 2줄 제목 + 3줄 본문 | — |
| `diagram` | `.venn` | 좌 6칼럼 도식 / 우 6칼럼 카드 3 + 노트 | 카드 3~4 |
| `cards` | (기본) | 카드 그리드 3×2 · 4×1 · 6칸 | 6칸 |
| `case` | `.brandcase` | 머리(메타+타이틀) / 좌 본문+증빙 / 우 미디어 / 하단 전체폭 표 | 아래 규칙 |
| `wall` | `.shorts` `.thumbs` | 미디어 월. 9:16 = 6열×2행 12칸 / 16:9 = 4열×2행 8칸 | 12 · 8 |
| `table` | `.plans` `.tbl` | 좌우 2열 표 + 옵션 박스 + 각주 | — |
| `logos` | `.logos` | 6열 그리드 | 30 |
| `shots` | `.board` | 좌 4칼럼 2단 / 우 8칼럼 메인 | 3컷 |

## 유형별 규칙

### `case` — 브랜드 케이스 (가장 자주 터지는 유형)

한 장에 들어가는 것: 메타 한 줄 · 타이틀 · 스탯 2~3 · 본문 문단 · 증빙 · 미디어.

- **증빙은 한 장만.** 여러 장이 매칭돼도 `EV_ON_CASE = 1`. 지표가 개선되는
  표(`kind: 퍼포먼스`)를 `PERF_FIRST` 로 먼저 세운다.
- **증빙이 붙으면 본문은 두 문단까지.** 세 문단 + 증빙이면 밴드를 넘는다.
  글을 줄여 증빙 자리를 만든다.
- **가로:세로 5:1 이상인 표는 전체 폭**(`.bc-ev-wide`). 절반 폭에 두면 글자가
  5pt 아래로 눌려 아무도 못 읽는다. 그 미만은 왼쪽 열(`.bc-ev`).
- 증빙 이미지는 `flex:1 1 0` + `object-fit:contain` — 넘치는 대신 줄어든다.

### `wall` — 미디어 월

- 9:16 숏폼은 6열 × 2행 = **12칸**, 16:9 롱폼은 4열 × 2행 = **8칸**.
- **장 수는 (편수 ÷ 정원) 을 올림하지 말고 반씩 나눈다.** 14편을 8+6 으로
  끊으면 둘째 장에 빈 칸 2개가 그대로 인쇄된다. `Math.ceil(len/2)` 로 7+7.
- 썸네일은 전부 **링크**다. 숏폼은 `hgrs.io/portfolio/clips/*.mp4`, 롱폼은
  `ytWatch(id)`. PDF 는 영상을 재생하지 못한다 — 크롬 인쇄가 앵커를 링크
  주석으로 보존하므로 **누르면 브라우저에서 열린다.**
- 브랜드 균형: `CLIP_CAP` 으로 브랜드당 상한을 걸고 라운드로빈으로 뽑는다.
  한 장에 한두 브랜드만 보이면 "그 업종 전문"으로 읽힌다.

### `cards` — 카드 그리드

- 6칸(3열×2행)이 기본. 항목이 6의 배수가 아니면 마지막 장에 빈 칸이 남는다 —
  검사기가 `빈칸` 으로 알려 주지만 잘못은 아니다.
- 카드 높이 = `(--body-h - gap) / 행수`. 카드 안 글은 **두 줄 안**.

### `diagram` — 도식

- 도식 컨테이너 높이는 `--body-h` 를 넘지 않는다.
- **벤 3원**: 지름 78mm, 중심 삼각형 한 변 48mm → 세로 오프셋 48×0.866 ≈ 42mm.
  컨테이너 높이 = 78 + 42 = 120mm.
  - 위 왼쪽 `left: calc(50% - 63mm); top: 0`
  - 위 오른쪽 `left: calc(50% - 15mm); top: 0`
  - 아래 가운데 `left: calc(50% - 39mm); top: 42mm`
  - 교집합 라벨 `left: 50%; top: 58mm` (세 중심의 무게중심보다 조금 아래가
    눈에 맞다)
  - 각 원의 글자는 겹치지 않는 바깥 잎으로 `transform: translate` 로 민다.
  - 색: 시딩 `--indigo` 16% / 숏폼 `--gold` 24% / 채널 `--navy` 16%

### `logos`

- 로고는 `/public/logos/{slug}.png`, 560×160 동일 캔버스. grayscale.
- 사이트(`components/landing/s-clients.tsx`)와 **개수를 맞춘다.**

## 목차 구간

장표는 `pages.push()` 순서대로 나가지 않는다. `sec("키")` 로 구간을 찍고
`ORDER` 대로 다시 세운다. **코드 블록을 옮기지 않고 목차를 바꿀 수 있다.**
같은 구간 안에서는 코드에 적힌 순서 그대로.

```
cover → hook → identity → lines → corp
      → part-made → made
      → part-numbers → numbers
      → how
      → part-imc → imc
      → start → close
```

| 구간 | 내용 |
|---|---|
| `cover` | 표지 |
| `hook` | 관점 선언 |
| `identity` | 해그로시 서비스 영역 (벤 3원) |
| `lines` | 세 갈래 진입 (LINE 01/02/03) |
| `corp` | 법인 정보 · 클라이언트 로고월 |
| `made` | 숏폼 · 롱폼 포트폴리오 |
| `numbers` | 브랜드별 성과 + 실적 증빙 |
| `how` | 프로세스 · 대시보드 · 조직 · SNS 시스템 |
| `imc` | IMC 28건 · 통합 브랜드 액션 |
| `start` | 숏폼 플랜 · SNS/종합 계약 구조 · 계약 결제 |
| `close` | 문의처 |

`ORDER` 에 없는 구간을 쓰면 빌드가 멈춘다.

## 값은 어디서 오는가

**가격·단계·정책 문구를 소개서에 직접 쓰지 않는다.** 사이트만 고치고 소개서가
옛 값을 들고 다니는 걸 막기 위함이다.

| 무엇 | 어디서 |
|---|---|
| 플랜·가격·옵션·정책 | `lib/constants.ts` (`PLANS` `MODEL_OPTION` `POLICY` `COMPANY` `SERVICE`) |
| 숏폼 소재 목록 | `lib/clips.ts` (`CLIPS_BY_BRAND` `clipPoster` `ytWatch`) |
| SNS 파트 전량 | `lib/sns-brand.ts` (`PROCESS` `FEATURES` `TEAM` `PORTFOLIO` `ACTIONS`) |
| IMC 28건 | `lib/framer-portfolio.ts` |
| 실적 증빙 | `public/evidence/index.json` (`scripts/evidence-prep.ts` 가 만든다) |

`build-deck.ts` 안에 남아 있는 하드코딩: `CLIENTS`(로고 슬러그) ·
`CASES`(숏폼 브랜드 케이스 수치) · `MOEV_ROAS` · `FLOW` · `CONTRACT` ·
`CREDENTIALS` · 표지 커버 스탯. 이것들은 아직 `lib/` 에 대응 데이터가 없다.

## 검사기가 보는 것

`npm run deck:doctor` (`scripts/deck-doctor.mjs`)

| 항목 | 뜻 | 심각도 |
|---|---|---|
| **넘침** | 안전영역 밖으로 나간 요소 — 인쇄에서 잘린다 | 실패 |
| **잘림** | `overflow:hidden` 인데 내용이 그릇보다 큼 | 실패 |
| **미로딩** | `naturalWidth === 0` 인 이미지 (경로 오타·누락) | 실패 |
| **빈칸** | 그리드 정원보다 적게 들어간 장 | 경고 |

정원은 고정값이 아니라 **덱 안에서 가장 많이 들어간 장** 기준이다.

넘침·잘림·미로딩이 하나라도 있으면 종료 코드 1. **"고쳤다"고 말하기 전에
이걸 돌린다.**
