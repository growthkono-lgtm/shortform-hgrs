## 판단 근거가 필요한 결정들

### 디자인 — 액센트는 `#B88C8C`

hgrs.io 라이브 CSS를 긁어보니 눈에 띄는 `#0099FF`는 **Framer 기본 링크 색**이었다.
실제 포인트 컬러는 1·2·3 넘버링 카드의 숫자에 쓰인 **`#B88C8C`**(뮤트된 더스티 로즈).
스펙 S8이 "hgrs.io 1·2·3 패턴"을 지목한 바로 그 요소라 이걸 `--accent`로 잡았다.
파란색은 사용 금지로 주석에 박아둠.

추출한 실측값: 텍스트 `#030303` / 보조 `#595959` / 섹션 배경 `#F7F7F7` /
헤드라인 자간 `-0.04em` / 영문 아이브로우 `+0.02em`.
서체는 라틴 Inter, 한글 **펴진고딕**(Pretendard 기반, SIL OFL — 자체 호스팅).

### 그로스 AI — 스펙의 sonnet-4-6 대신 opus-5, effort=medium

브랜드당 1회만 도는 호출이라 비용 영향이 작고, 여기서 뽑은 USP·타겟이
이후 모든 캠페인 기획의 입력이 된다.
effort는 기본값 `high`에서 **178초**가 걸려 온보딩 UX가 무너졌다.
`medium`으로 낮추니 **45초**, 품질은 유지(USP 3개·금지표현 5개 동일 수준, 헤드라인은 오히려 더 날카로움).

### 결제 — 금액은 서버가 `plans`에서 읽는다

클라이언트가 보낸 금액은 받지도 않는다. 리다이렉트로 돌아온 금액은 대조용.
실제로 4가지 공격 경로를 때려서 확인했다.

| 시나리오 | 결과 |
| --- | --- |
| 금액 조작 (₩2,200,000 → ₩1,000) | `AMOUNT_MISMATCH` 차단 |
| 존재하지 않는 주문 | 차단 |
| 파라미터 누락 | 차단 |
| 정상 금액 + 위조 결제키 | 토스가 `NOT_FOUND_PAYMENT_SESSION` 반환 |

마지막 항목이 시크릿 키 인증이 정상이라는 증거(키가 틀리면 `UNAUTHORIZED_KEY`).

### RLS — `private.is_admin()`에 EXECUTE를 돌려줘야 했다

보안 가이드대로 EXECUTE를 회수했더니 **본인 프로필 조회까지 실패**했다.
RLS 정책은 쿼리를 던진 롤의 권한으로 평가되기 때문.
`authenticated`에만 돌려주고 `anon`은 차단. `private` 스키마는 Data API 미노출이라 외부 호출 경로는 없다.

격리 검증 완료: 사용자1/2가 서로의 행을 못 보고, 비로그인은 `profiles` 빈 배열,
`orders` 직접 INSERT는 `42501`로 차단.

### 자산 — 파일명을 믿으면 안 됐다

Drive 영상 8개를 하나씩 열어보니 파일명과 내용이 달랐다.

| 파일명 | 실제 |
| --- | --- |
| `tpu 비교.mp4` | 비교 영상 아님 → 앞은 **후기형**(평점 4.92), 뒤는 **비교형**("어떤 매트든") |
| `제로블럭 인터뷰` | 인터뷰 아님 → **비포애프터형** |
| `0401_흰색배경` | **제품 실험형** |

파일명대로 매핑했으면 포맷 메뉴판 4칸이 전부 틀렸을 것.
`consultant-sgh`의 `production` 6장도 "촬영 현장"이 아니라 **SEO 구조도·검색결과·서치콘솔 화면**이었다.

### 성과 섹션(S5)은 구조를 바꿨다

ROAS/CTR/CPA 원본 지표가 없어서, 후기에 담긴 **브랜드가 직접 밝힌 결과**로 재구성.
화면에 "브랜드가 전해온 결과, 우리가 산출한 추정치 아님"을 명시.
지표 데이터가 오면 원래 구조(전후 그래프)로 되돌리면 된다.

### 마퀴 타일은 `next/image`를 쓰지 않는다

트랙을 두 벌 이어붙이므로 60장 × 2 = **120건의 런타임 최적화 요청**이 생겨 첫 렌더가 막혔다.
이미 webp로 압축된 자산이라 plain `<img loading="lazy">`로 충분하다.

### 런칭 전 반드시 처리 (보안·운영)

1. **인증 메일 SMTP 미설정** — 지금은 Supabase 내장 발송(시간당 2건, 조직 멤버 주소만).
   이대로 열면 **실제 고객이 가입 인증 메일을 못 받는다.** Resend SMTP 연결 필요.
2. **Site URL이 `localhost:3000`** — 배포 시 인증 메일 링크가 localhost로 감.
3. **비밀번호 최소 길이** — 폼은 8자로 막지만 Supabase 설정은 6자라 API 직접 호출 시 통과.
4. **개발용 테스트 계정 2개** (`dev-test@`, `dev-test2@hgrs-boost.local`) — 런칭 전 삭제.
5. **리전이 싱가포르**(`ap-southeast-1`) — 국내 기준 왕복 60~80ms 추가. 데이터 없는 지금이 이전 비용 최저.

## 판단 근거가 필요한 결정들 (2일차)

### 색 — 1일차 결론이 틀렸다

1일차에 "hgrs.io의 `#0099FF`는 Framer 기본 링크색이라 브랜드색이 아니다"까지는 맞았는데,
거기서 **"그러니 블루는 브랜드색이 아니다"로 잘못 결론냈다.**
실제 hgrs.io 히어로에는 두 곡선이 교차한다 — **인디고 `#4D5FE8`**(Project Story 풀블록 패널)과
**골드탄 `#B89B8D`**. 이 둘이 브랜드 2색이다.

역할을 나눴다. 섞어 쓰면 탁해진다.

| 색 | 역할 |
| --- | --- |
| 인디고 `#4D5FE8` / `#3948B8` | CTA·넘버링·강조·표 하이라이트 — **전경 전담** |
| 골드탄 `#B89B8D` / `#8E6B68` | 아이브로우, 섹션 교차 배경(`#f7f5f3`), 히어로 곡선 — **배경 전담** |

골드를 전경 강조색(금액·뱃지)으로 써봤다가 탁해져서 되돌렸다.

### 서체 — Inter가 아니라 DM Sans

hgrs.io 실측(`document.fonts` + computed style): 한글 **Pyeojin Gothic**, 라틴 **DM Sans**.
1일차엔 라틴을 Inter로 잡아 뒀는데 hgrs.io는 Inter를 안 쓴다.

### 한글 줄바꿈 — `word-break: keep-all` 은 필수다

브라우저 기본값은 "요즘 브랜드의 필수 요 / 소," 처럼 **단어 한가운데를 끊는다.**
전역으로 `keep-all` + 본문에 `text-wrap: pretty`를 걸었다. 취향 문제가 아니다.

### 성장 사례 — 사례당 소재는 정확히 하나

사장님이 브랜드별로 직접 지정했다. 여백이 남아 같은 브랜드 소재를 한 편만 더 붙였고,
**다른 브랜드 소재는 절대 섞지 않는다** — 그 소재가 낸 성과처럼 읽힌다.
사례↔성과문구 대응은 피그마 캔버스 Y좌표로 확인했다(추정 아님).

| --- | --- | --- |
| 뤼이드 리얼 아카데미 (투자 2,000억) | 아웃풋레포트 + 맘카페 | 3주 연속 고지출 & CPA 견인 |

### 크기를 CSS `scale` 로 맞추지 말 것

로고마다 눈대중 배율을 주면 화면 폭이 바뀔 때마다 다시 어긋난다.
**파일 자체를 규격화**했다 — `scratchpad/normalize2.py`:
잉크 경계를 픽셀로 재서 여백 제거 → 가로:세로 비율대로 광학 크기 정렬 → 440x110 동일 캔버스.
그 다음 CSS에서 배율을 하나도 주지 않는다.

### ffmpeg 함정 세 개 (전부 여기서 밟았다)

1. **`cropdetect` 가 흰 배경 캡처본에서 안 먹는다.** 투명 배경 로고와 조건이 달라서.
   → 알파+밝기로 직접 판정 (`ink_bbox`)
2. **`color=white` lavfi 합성은 홀수 높이에서 한 줄을 잘라먹는다** (yuv420p 크로마 서브샘플링).
   1024x169 로고가 172032 바이트로 나와 계산이 어긋났다. → 합성 없이 RGBA raw 직접 읽기
3. **`format=rgba` 를 필터 체인 맨 앞에 안 두면 알파가 날아간다.**
   투명 배경이 불투명 회색 사각형으로 구워져 화면에 그대로 나갔다.
   출력에도 `-pix_fmt rgba` 를 고정할 것.

### 카운트업이 크롤러에 0으로 나가고 있었다 (S7)

`GrowthMeter`·`RoasCounter` 둘 다 `useState(0)`(RoasCounter는 첫 단계 `"10"`)에서
시작해 화면 진입 시 목표치까지 올리는 구조였다. 그래서 **JS가 안 도는 환경**
— 검색 크롤러, 카카오·슬랙 링크 미리보기, 일부 인앱브라우저 — 에서 성과가 전부

```
0주  ▼0위  0배  ₩0만  ▼0만원      ROAS 10
```

으로 노출됐다. 성과 섹션이 통째로 0인 페이지가 링크로 돌아다닌 셈이다.

**고친 방식** — 진행도 `p`의 초기값을 `1`(=최종값)로 두고, 애니메이션을
progressive enhancement로만 붙인다. 공통 규칙은 `components/ui/use-count-up.ts`
한 곳에 있고 `GrowthMeter`·`RoasCounter`·히어로 숫자칩이 공유한다.

#### 여기서 한 번 갈렸던 판단 — `useLayoutEffect` 로 0으로 되돌리면 되지 않나

안 된다. **초기 HTML은 하이드레이션보다 먼저 페인트된다.** 최종값을 그려 놓고
하이드레이션 후에 0으로 되돌리면, 사용자 눈에는

> `30+` 이 떴다가 → `0` 으로 튀고 → 다시 올라간다

로 보인다. 하이드레이션이 느린 모바일에서 이 간격이 그대로 노출된다.
`useLayoutEffect`는 **그 커밋의** 페인트만 막아 줄 뿐, 이미 나간 첫 페인트는 못 되돌린다.

그래서 규칙을 이렇게 잡았다:

| 상황 | 동작 |
| --- | --- |
| 마운트 시점에 **이미 화면 안** (히어로 숫자칩) | 애니메이션 걸지 않음. 최종값 그대로 |
| 마운트 시점에 **화면 밖** (성장 사례 대부분) | 0으로 되돌린 뒤 스크롤 진입 시 카운트업 |
| `prefers-reduced-motion` | 최종값 그대로 |

화면 밖에서 0으로 되돌리는 건 눈에 안 보이므로 깜빡임이 없다.
**트레이드오프**: 히어로 숫자칩은 실제로 카운트업이 돌지 않는다(정적 렌더).
기획안은 카운트업을 요청했지만, 하드 요구사항(JS 없이 최종값 노출)과 충돌할 때는
후자를 택했다. 히어로에서 숫자가 튀는 것보다 가만히 있는 편이 낫다.

### 모바일에서 1px 때문에 깨질 뻔한 것

좁은 화면에서만 마지막 칸에 폭을 더 준다 — `grid-cols-[1fr_1fr_1.4fr] sm:grid-cols-3`.
(눈으로 안 보이는 차이라 브라우저에서 폰트 실측으로 확인했다. 320px SE 기준까지 여유 확인.)

### 컨텐츠 진단 (`lib/diagnosis.ts` · `s-diagnosis.tsx`)

신청 폼 앞에 5문항을 놓았다 — USP 이해도 / 목적 / 소스 보유 / 소재 재고 / 필요 물량.
문항마다 **왜 묻는지 한 줄**을 붙였다. 답을 조합해 플랜과 근거를 돌려준다.

- 소스가 없다 → 시딩으로 소스컷부터 확보 → 패키지
- 소스가 충분하다 → 숏폼 기획제작만 → 싱글
- 물량·목적으로 스타터/그로스/스케일 결정

진단 결과에서 **"헤드에게 문의" · "상담 신청" 류 CTA는 전부 뺐다.** 우리는 상담을 파는
회사가 아니다. AI가 쓴 티 나는 결과 헤드라인도 뺐다(`headline`은 코드에만 남고 화면에 안 나감).

진단에서 고른 값은 **아래 신청 폼에 그대로 체크된 채로 내려온다**(`diagnosis-context.tsx`).
같은 걸 두 번 묻지 않는다.

### 가입 — 이메일 3단계

소셜 로그인 없이 **이메일 + 비밀번호**. 우리 DB에 남기고 나중에 이메일 마케팅을 하려면
소셜로는 안 된다.

1. 이메일 입력 → 인증번호 발송
2. 인증번호 확인
3. 비밀번호 / 회사명 / 담당자 이름 / 직책 → 가입 완료 → 대시보드

동의는 2건. **개인정보 보호법 제15조**(수집·이용) / **정보통신망법 제50조**(광고성 정보 수신).

**이메일 도메인 필터링은 없다.** 지메일·네이버 다 된다 — 실무 담당자는 회사 메일을 안 쓴다.

브라우저로 주입하는 우회는 하지 않았다).

### 다시 밟은 함정 — CSS Grid `min-width: auto`

모바일 히어로가 잘리는 문제를 **두 번** 겪었다. 첫 시도는 텍스트 열에 `min-w-0`을
붙였는데 대상이 틀렸다. 진범은 `-mx-5 lg:hidden` 마퀴 래퍼로, 내부 폭이 3,208px라
그리드 트랙을 통째로 밀어내고 있었다. 래퍼에 `min-w-0 overflow-hidden`.

검증은 **390px iframe**으로 했다(이 환경에선 창 리사이즈가 안 먹는다).
`documentElement.scrollWidth − innerWidth = 0` 확인.

> 그리드 자식은 기본이 `min-width: auto`라 **내용보다 작아지지 않는다.**
> 가로로 흐르는 요소를 넣을 땐 그 요소의 래퍼에 `min-w-0`을 붙인다. 세 번째는 없어야 한다.
