## 판단 근거가 필요한 결정들

### 디자인 — 액센트는 `#B88C8C`

hgrs.io 라이브 CSS를 긁어보니 눈에 띄는 `#0099FF`는 **Framer 기본 링크 색**이었다.
실제 포인트 컬러는 1·2·3 넘버링 카드의 숫자에 쓰인 **`#B88C8C`**(뮤트된 더스티 로즈).
스펙 S8이 "hgrs.io 1·2·3 패턴"을 지목한 바로 그 요소라 이걸 `--accent`로 잡았다.
파란색은 사용 금지로 주석에 박아둠.

추출한 실측값: 텍스트 `#030303` / 보조 `#595959` / 섹션 배경 `#F7F7F7` /
헤드라인 자간 `-0.04em` / 영문 아이브로우 `+0.02em`.
서체는 라틴 Inter, 한글 **펴진고딕**(Pretendard 기반, SIL OFL — 자체 호스팅).

### 그로스 AI — 스펙의 sonnet-4-6 대신 opus-5, effort=medium

브랜드당 1회만 도는 호출이라 비용 영향이 작고, 여기서 뽑은 USP·타겟이
이후 모든 캠페인 기획의 입력이 된다.
effort는 기본값 `high`에서 **178초**가 걸려 온보딩 UX가 무너졌다.
`medium`으로 낮추니 **45초**, 품질은 유지(USP 3개·금지표현 5개 동일 수준, 헤드라인은 오히려 더 날카로움).

### 결제 — 금액은 서버가 `plans`에서 읽는다

클라이언트가 보낸 금액은 받지도 않는다. 리다이렉트로 돌아온 금액은 대조용.
실제로 4가지 공격 경로를 때려서 확인했다.

| 시나리오 | 결과 |
| --- | --- |
| 금액 조작 (₩2,200,000 → ₩1,000) | `AMOUNT_MISMATCH` 차단 |
| 존재하지 않는 주문 | 차단 |
| 파라미터 누락 | 차단 |
| 정상 금액 + 위조 결제키 | 토스가 `NOT_FOUND_PAYMENT_SESSION` 반환 |

마지막 항목이 시크릿 키 인증이 정상이라는 증거(키가 틀리면 `UNAUTHORIZED_KEY`).

### RLS — `private.is_admin()`에 EXECUTE를 돌려줘야 했다

보안 가이드대로 EXECUTE를 회수했더니 **본인 프로필 조회까지 실패**했다.
RLS 정책은 쿼리를 던진 롤의 권한으로 평가되기 때문.
`authenticated`에만 돌려주고 `anon`은 차단. `private` 스키마는 Data API 미노출이라 외부 호출 경로는 없다.

격리 검증 완료: 사용자1/2가 서로의 행을 못 보고, 비로그인은 `profiles` 빈 배열,
`orders` 직접 INSERT는 `42501`로 차단.

### 자산 — 파일명을 믿으면 안 됐다

Drive 영상 8개를 하나씩 열어보니 파일명과 내용이 달랐다.

| 파일명 | 실제 |
| --- | --- |
| `tpu 비교.mp4` | 비교 영상 아님 → 앞은 **후기형**(평점 4.92), 뒤는 **비교형**("어떤 매트든") |
| `제로블럭 인터뷰` | 인터뷰 아님 → **비포애프터형** |
| `0401_흰색배경` | **제품 실험형** |

파일명대로 매핑했으면 포맷 메뉴판 4칸이 전부 틀렸을 것.
`consultant-sgh`의 `production` 6장도 "촬영 현장"이 아니라 **SEO 구조도·검색결과·서치콘솔 화면**이었다.

### 성과 섹션(S5)은 구조를 바꿨다

ROAS/CTR/CPA 원본 지표가 없어서, 후기에 담긴 **브랜드가 직접 밝힌 결과**로 재구성.
화면에 "브랜드가 전해온 결과, 우리가 산출한 추정치 아님"을 명시.
지표 데이터가 오면 원래 구조(전후 그래프)로 되돌리면 된다.

### 마퀴 타일은 `next/image`를 쓰지 않는다

트랙을 두 벌 이어붙이므로 60장 × 2 = **120건의 런타임 최적화 요청**이 생겨 첫 렌더가 막혔다.
이미 webp로 압축된 자산이라 plain `<img loading="lazy">`로 충분하다.

### 런칭 전 반드시 처리 (보안·운영)

1. **인증 메일 SMTP 미설정** — 지금은 Supabase 내장 발송(시간당 2건, 조직 멤버 주소만).
   이대로 열면 **실제 고객이 가입 인증 메일을 못 받는다.** Resend SMTP 연결 필요.
2. **Site URL이 `localhost:3000`** — 배포 시 인증 메일 링크가 localhost로 감.
3. **비밀번호 최소 길이** — 폼은 8자로 막지만 Supabase 설정은 6자라 API 직접 호출 시 통과.
4. **개발용 테스트 계정 2개** (`dev-test@`, `dev-test2@hgrs-boost.local`) — 런칭 전 삭제.
5. **리전이 싱가포르**(`ap-southeast-1`) — 국내 기준 왕복 60~80ms 추가. 데이터 없는 지금이 이전 비용 최저.

## 판단 근거가 필요한 결정들 (2일차)

### 색 — 1일차 결론이 틀렸다

1일차에 "hgrs.io의 `#0099FF`는 Framer 기본 링크색이라 브랜드색이 아니다"까지는 맞았는데,
거기서 **"그러니 블루는 브랜드색이 아니다"로 잘못 결론냈다.**
실제 hgrs.io 히어로에는 두 곡선이 교차한다 — **인디고 `#4D5FE8`**(Project Story 풀블록 패널)과
**골드탄 `#B89B8D`**. 이 둘이 브랜드 2색이다.

역할을 나눴다. 섞어 쓰면 탁해진다.

| 색 | 역할 |
| --- | --- |
| 인디고 `#4D5FE8` / `#3948B8` | CTA·넘버링·강조·표 하이라이트 — **전경 전담** |
| 골드탄 `#B89B8D` / `#8E6B68` | 아이브로우, 섹션 교차 배경(`#f7f5f3`), 히어로 곡선 — **배경 전담** |

골드를 전경 강조색(금액·뱃지)으로 써봤다가 탁해져서 되돌렸다.

### 서체 — Inter가 아니라 DM Sans

hgrs.io 실측(`document.fonts` + computed style): 한글 **Pyeojin Gothic**, 라틴 **DM Sans**.
1일차엔 라틴을 Inter로 잡아 뒀는데 hgrs.io는 Inter를 안 쓴다.

### 한글 줄바꿈 — `word-break: keep-all` 은 필수다

브라우저 기본값은 "요즘 브랜드의 필수 요 / 소," 처럼 **단어 한가운데를 끊는다.**
전역으로 `keep-all` + 본문에 `text-wrap: pretty`를 걸었다. 취향 문제가 아니다.

### 성장 사례 — 사례당 소재는 정확히 하나

사장님이 브랜드별로 직접 지정했다. 여백이 남아 같은 브랜드 소재를 한 편만 더 붙였고,
**다른 브랜드 소재는 절대 섞지 않는다** — 그 소재가 낸 성과처럼 읽힌다.
사례↔성과문구 대응은 피그마 캔버스 Y좌표로 확인했다(추정 아님).

| --- | --- | --- |
| 뤼이드 리얼 아카데미 (투자 2,000억) | 아웃풋레포트 + 맘카페 | 3주 연속 고지출 & CPA 견인 |

### 크기를 CSS `scale` 로 맞추지 말 것

로고마다 눈대중 배율을 주면 화면 폭이 바뀔 때마다 다시 어긋난다.
**파일 자체를 규격화**했다 — `scratchpad/normalize2.py`:
잉크 경계를 픽셀로 재서 여백 제거 → 가로:세로 비율대로 광학 크기 정렬 → 440x110 동일 캔버스.
그 다음 CSS에서 배율을 하나도 주지 않는다.

### ffmpeg 함정 세 개 (전부 여기서 밟았다)

1. **`cropdetect` 가 흰 배경 캡처본에서 안 먹는다.** 투명 배경 로고와 조건이 달라서.
   → 알파+밝기로 직접 판정 (`ink_bbox`)
2. **`color=white` lavfi 합성은 홀수 높이에서 한 줄을 잘라먹는다** (yuv420p 크로마 서브샘플링).
   1024x169 로고가 172032 바이트로 나와 계산이 어긋났다. → 합성 없이 RGBA raw 직접 읽기
3. **`format=rgba` 를 필터 체인 맨 앞에 안 두면 알파가 날아간다.**
   투명 배경이 불투명 회색 사각형으로 구워져 화면에 그대로 나갔다.
   출력에도 `-pix_fmt rgba` 를 고정할 것.

### 카운트업이 크롤러에 0으로 나가고 있었다 (S7)

`GrowthMeter`·`RoasCounter` 둘 다 `useState(0)`(RoasCounter는 첫 단계 `"10"`)에서
시작해 화면 진입 시 목표치까지 올리는 구조였다. 그래서 **JS가 안 도는 환경**
— 검색 크롤러, 카카오·슬랙 링크 미리보기, 일부 인앱브라우저 — 에서 성과가 전부

```
0주  ▼0위  0배  ₩0만  ▼0만원      ROAS 10
```

으로 노출됐다. 성과 섹션이 통째로 0인 페이지가 링크로 돌아다닌 셈이다.

**고친 방식** — 진행도 `p`의 초기값을 `1`(=최종값)로 두고, 애니메이션을
progressive enhancement로만 붙인다. 공통 규칙은 `components/ui/use-count-up.ts`
한 곳에 있고 `GrowthMeter`·`RoasCounter`·히어로 숫자칩이 공유한다.

#### 여기서 한 번 갈렸던 판단 — `useLayoutEffect` 로 0으로 되돌리면 되지 않나

안 된다. **초기 HTML은 하이드레이션보다 먼저 페인트된다.** 최종값을 그려 놓고
하이드레이션 후에 0으로 되돌리면, 사용자 눈에는

> `30+` 이 떴다가 → `0` 으로 튀고 → 다시 올라간다

로 보인다. 하이드레이션이 느린 모바일에서 이 간격이 그대로 노출된다.
`useLayoutEffect`는 **그 커밋의** 페인트만 막아 줄 뿐, 이미 나간 첫 페인트는 못 되돌린다.

그래서 규칙을 이렇게 잡았다:

| 상황 | 동작 |
| --- | --- |
| 마운트 시점에 **이미 화면 안** (히어로 숫자칩) | 애니메이션 걸지 않음. 최종값 그대로 |
| 마운트 시점에 **화면 밖** (성장 사례 대부분) | 0으로 되돌린 뒤 스크롤 진입 시 카운트업 |
| `prefers-reduced-motion` | 최종값 그대로 |

화면 밖에서 0으로 되돌리는 건 눈에 안 보이므로 깜빡임이 없다.
**트레이드오프**: 히어로 숫자칩은 실제로 카운트업이 돌지 않는다(정적 렌더).
기획안은 카운트업을 요청했지만, 하드 요구사항(JS 없이 최종값 노출)과 충돌할 때는
후자를 택했다. 히어로에서 숫자가 튀는 것보다 가만히 있는 편이 낫다.

### 컨텐츠 진단 (`lib/diagnosis.ts` · `s-diagnosis.tsx`)

신청 폼 앞에 5문항을 놓았다 — USP 이해도 / 목적 / 소스 보유 / 소재 재고 / 필요 물량.
문항마다 **왜 묻는지 한 줄**을 붙였다. 답을 조합해 플랜과 근거를 돌려준다.

- 소스가 충분하다 → 숏폼 기획제작만 → 싱글
- 물량·목적으로 스타터/그로스/스케일 결정

진단 결과에서 **"헤드에게 문의" · "상담 신청" 류 CTA는 전부 뺐다.** 우리는 상담을 파는
회사가 아니다. AI가 쓴 티 나는 결과 헤드라인도 뺐다(`headline`은 코드에만 남고 화면에 안 나감).

진단에서 고른 값은 **아래 신청 폼에 그대로 체크된 채로 내려온다**(`diagnosis-context.tsx`).

### 다시 밟은 함정 — CSS Grid `min-width: auto`

모바일 히어로가 잘리는 문제를 **두 번** 겪었다. 첫 시도는 텍스트 열에 `min-w-0`을
붙였는데 대상이 틀렸다. 진범은 `-mx-5 lg:hidden` 마퀴 래퍼로, 내부 폭이 3,208px라
그리드 트랙을 통째로 밀어내고 있었다. 래퍼에 `min-w-0 overflow-hidden`.

검증은 **390px iframe**으로 했다(이 환경에선 창 리사이즈가 안 먹는다).
`documentElement.scrollWidth − innerWidth = 0` 확인.

> 그리드 자식은 기본이 `min-width: auto`라 **내용보다 작아지지 않는다.**
> 가로로 흐르는 요소를 넣을 땐 그 요소의 래퍼에 `min-w-0`을 붙인다. 세 번째는 없어야 한다.

## 2026-08-11 — 5일차 · 소개서(PDF) 제작과 발송 파이프라인

4일차가 "한 바퀴 도는 서비스"였다면 5일차는 **파는 문서**를 만들었다.
플랜 문의가 들어오면 나가는 소개서 한 부와, 그것을 실어 보내는 메일이다.

### 소개서는 홈페이지 복사본이 아니다

처음엔 홈페이지 내용을 A4 세로로 옮겨 15페이지를 만들었다. 그건 소개서가 아니라
**문서화된 홈페이지**였다. 사장님 지적으로 세 번 갈아엎었다.

| 회차 | 무엇이 틀렸나 | 어떻게 고쳤나 |
| --- | --- | --- |
| 1차 | 홈페이지를 옮겨 적기만 함 | 시장 구조·포지션·통합 라인 도식을 세워 **제안서**로 |
| 2차 | 글줄이 흐르는 장표, 워드 문서 같음 | 16:9 슬라이드로 전환, 도형·숫자·실제 화면으로 |
| 3차 | 제목을 전부 존댓말 문장으로 달아 어느 장인지 안 보임 | **키워드를 헤드라인(26pt)**, 제안 문장을 서브라인(15pt)으로 |

최종 17장.
표지 → 법인 소개 → 시장 구조 → 포지션 → 진행 라인 → 기대 효과 → 제작 조직 →
역할 구성 → 제작 시스템 → 클라이언트 히스토리 → 주요 성과 → 최근 주요 포트폴리오 →
진행 프로세스 → 내 프로젝트 → **플랜 안내** → 계약·결제 → 문의처.

### 조판에서 배운 것

- **키워드가 먼저 크게 보여야 한다.** 키워드를 작은 라벨로 내렸더니 제안 문장을
  읽어 주지도 않았다. 순서를 뒤집으니 바로 읽혔다
- **서브라인은 핵심 한 줄이다.** 더미텍스트 크기(9.5pt)로 줄여 뒀더니 안 읽혔다 → 15pt
- **색은 글자가 아니라 면에 쓴다.** 카피에 색을 입히는 것보다 배경·도형에 인디고와
  골드탄을 채우는 쪽이 훨씬 강했다
- **3인칭 소개투 금지.** "이런 분들이 만듭니다"는 남을 소개하는 말이다.
  우리가 우리를 소개하는 문서다
- **플랜은 중간에 두면 못 찾는다.** 뒷단(내 프로젝트 다음, 계약 앞)으로 옮겼다

### 실제 화면을 넣었다

목업이 아니라 라이브에서 캡처했다 — 내 프로젝트 대시보드, 1차 선정 심사(팔로워·평균
조회·CPV), 브랜드 AI 기본 분석. `public/deck/` 에 파일로 둔다.
성과 사례 4건에도 실제 소재 이미지를 넣었다(뤼이드·파크론·모에브·크래프톤).

### 값은 코드에서 읽는다

가격·단계·정책 문구를 소개서에 **하드코딩하지 않았다.** `lib/constants.ts` 와
`lib/stages.ts` 에서 읽는다. 하드코딩해 두면 사이트만 고치고 소개서는 옛 가격을
들고 돌아다니게 된다.


**`www` 리다이렉트를 걸었다가 뺐다.** apex 인증서가 발급되기 전 Vercel 이

이 null 이라 애니메이션이 끝 상태로 고정된다. `overflow:hidden` 조상 하나로도
비활성화된다. 검증 못 하는 걸 페이지 핵심 연출로 두지 않는다 →
`use-view-progress.ts` 로 JS 가 직접 잰다. 초기값은 항상 1(완성 상태)이라
JS 가 안 돌면 그냥 완성된 그림이 보인다.

고쳤다고 말하기 전에 실제 결과물을 본다.** 이 세션에서 만든 검사 스크립트 셋이

## 2026-08-13 — 8일차 · 작업자 대시보드 (별도 호스트)

영상 기획·제작을 맡길 외부 작업자용 표면을 만들었다. **레포도 DB도 하나다. 호스트만 다르다.**

### 왜 복사하지 않았나

작업자 화면과 클라이언트 화면은 같은 `deliverables` 행을 본다. 작업자가 결과물을 올리면
클라이언트 대시보드가 그 자리에서 바뀌어야 하고, 클라이언트가 누른 수정 요청이 작업자
카드에 그대로 떠야 한다. 레포를 복사하면 그 연결이 끊기고 두 벌을 평생 같이 고쳐야 한다.

### 가르는 지점은 네 군데다

| 층 | 조치 |
| --- | --- |
| 호스트 | `WORK_HOSTS` 에 걸린 도메인이면 `/work/**` 외 **전부 404** (`proxy.ts`). 리다이렉트가 아니라 404 — 리다이렉트는 "다른 곳이 있다"를 알려준다 |
| 페이지 소스 | 루트 레이아웃에서 JSON-LD(Organization/WebSite)와 채널톡을 걷어내 `app/(site)/layout.tsx` 로 내렸다. 기존 라우트 10개를 `(site)` 그룹으로 옮겼다(URL 불변) |
| 데이터 | 작업자 쿼리는 `profiles` / `plans` / `orders` / `inquiries` 를 **한 번도 조인하지 않는다.** 프로젝트 이름은 `projects.work_code`(W-0001) 하나뿐 |
| 브리프 | 클라 가이드라인 원문 대신 상호·브랜드명·URL을 걷어낸 `work_briefs` 파생본만 |

### 브라우저에 Supabase 클라이언트를 올리지 않는다

작업자 표면은 로그인까지 전부 서버 액션이다. `createBrowserClient` 를 한 번이라도 쓰면
`NEXT_PUBLIC_SUPABASE_ANON_KEY` 가 그 번들에 인라인된다. `plans` 는 랜딩이 읽어야 해서
anon SELECT 가 열려 있으므로, 키가 나가면 **가격표를 통째로 긁을 수 있다.**

실측 확인 — `/work/login` 이 부르는 청크 9개에 `해그로시` · `hgrs` · `*.supabase.co` ·
JWT 접두사 **0건**. 페이지 HTML에도 브랜드 문자열 0건.

### 호스트 분리 실측

```
work-host   /  307→/work/login   /work/login 200   /admin /shortform /login /signup 404
            /favicon.ico 404  /sitemap.xml 404  /robots.txt 404
main-host   / 200   /shortform 200   /work 404   /work/login 404
```

favicon 은 proxy matcher 에서 일부러 뺐다 — 제외해 두면 브라우저가 자동으로 긁어가
우리 파비콘이 그대로 나간다.

### 작업 트랙은 클라 트랙과 별개 컬럼이다

`deliverables.status`(클라가 보는 값)와 `work_status`(작업자·우리가 보는 값)를 나눴다.
합치면 작업자가 제출하는 순간 클라이언트 화면에 나간다. 두 값은 **승인 시점에만** 만난다.

```
brief → planning → plan_review → producing → submitted → delivered → (revising) → done
                     ↑우리                     ↑우리        ↑클라
```

승인 시 `work_url` 이 `preview_url` 로 올라가고 `status='preview'` 가 된다.
클라 수정 요청은 검수를 거치지 않고 바로 작업자에게 간다 — 클라가 직접 쓴 내용이라
우리가 다시 판단할 게 없고 하루를 번다.

### 브리프는 모델이 쓰고 사람은 검수만 한다

`lib/work-brief-ai.ts`(opus-5, effort medium). 지운 식별정보를 `redacted` 배열로 돌려주게
해서 어드민이 **그것부터** 보게 했다. `published_at` 이 찍혀야 작업자 화면에 나타나고,
다시 생성하면 공개가 자동으로 내려간다. 연타 방지는 서버에서 60초 — 화면에서 막으면

### 내 손이 가는 곳은 두 군데로 줄었다

## 2026-08-13 — 공정 재설계 (v2) · 5단계 · 라벨 두 벌 · 게이트 제거

1차에서 만든 8단계가 실제 일하는 방식과 달랐다. 송대표 지시로 갈아엎었다.

### 무엇이 틀렸었나

**"기획 작성중"이라는 단계.** 컨텐츠는 편당 들어가는데 프로젝트 하나에 기획 칸을 걸어 두니
작업자 입장에서 뭘 쓰라는 건지 알 수 없다. 게다가 그 기획안을 내가 검수해서 통과시켜야
제작으로 넘어갔다 — 내 손이 공정 한가운데에 박혀 있었다.

**AI가 브리프를 쓰는 구조.** 실제로는 내가 제품 링크·가격·현황·요청사항을 직접 적어 준다.
AI는 그걸 대신 쓰는 게 아니라, 그걸 **근거로 세부 자료조사**를 해 주는 보조여야 했다.

### 5단계 · 상태 하나 · 라벨 둘

`lib/work.ts` 의 `WORK_STAGES` 한 배열이 두 라벨을 다 갖는다. 상태를 두 벌로 나누면
두 화면이 반드시 어긋난다.

| key | 작업자가 보는 말 | 클라이언트가 보는 말 | 공 |
| --- | --- | --- | --- |
| `study` | 브랜드 정보 확인 | 담당자 브랜드 압축 스터디중 | 작업자 |
| `producing` | 컨텐츠 기획제작중 | 숏폼 기획제작 진행중 | 작업자 |
| `review` | 1차 완성본 컨펌 요청 | 1차 완성본 컨펌 확인 | **클라이언트** |
| `revising` | 최종 수정 반영중 | 최종 수정요청 반영중 | 작업자 |
| `done` | 최종본 전달 완료 | 최종본 다운로드/확인 | — |

작업자가 미는 전이는 셋(`study→producing`, `producing→review`, `revising→review`).
**review 에서 앞으로 가는 길은 클라이언트만 연다** — 수정 요청 또는 [이대로 확인 완료].
자기 결과물을 스스로 "확인됨"으로 넘길 수 있으면 안 된다.

### projects.stage_b 를 편에서 파생시켰다

클라이언트 대시보드는 프로젝트 단위 스텝퍼인데 진행은 편 단위다. 두 곳을 사람이 맞춰
누르면 반드시 어긋난다. **가장 뒤처진 편**을 프로젝트 단계로 삼는 트리거를 걸었다
(`sync_project_stage_b`). `lib/stages.ts` 의 `SHORTS_STAGES` 는 이제 같은 key 를 쓰는
클라이언트 라벨 사전일 뿐이다. 어드민의 숏폼 단계 수동 버튼은 없앴다.

실측: 편1만 `producing` → 프로젝트 `study` 유지 / 전 편 `review` → 프로젝트 `review` /
전 편 `study` 원복 → 프로젝트 `study`.

### 브랜드 정보는 사람이 쓰고, AI 는 그 아래로 내려갔다

`work_briefs` 를 갈아엎었다(AI 9칸 → 3칸).

| 칸 | 누가 | 어디에 뜨나 |
| --- | --- | --- |
| `manual_note` | 어드민이 수기 | 작업자 화면 맨 위 |
| `client_note` | 클라이언트가 포털에서 | 그 바로 아래 |
| `ai_analysis` | 작업자가 버튼으로 | 그 아래 (선택) |

AI 프롬프트는 "브리프 작성"에서 **"자료조사"**로 바꿨다 — 한 줄 요약 / 찾는 사람 /
소구점 / 훅 5개 / 톤 / 금지 표현 / **담당자에게 확인이 필요한 것**. 자료에 없는 사실을
만들지 말고 "확인 필요"로 남기라고 못 박았다. 지어낸 수치를 믿고 만든 영상이 나가면 끝이다.

작업자가 직접 돌리므로 비용 가드를 서버에 뒀다(프로젝트당 60초 쿨다운, 결과는 프로젝트
단위로 공유되어 같은 프로젝트의 다른 편에서도 그대로 보인다).

### 내 역할은 이만큼 남았다

신청 접수 → 상담/결제 → **작업자 배정**(전체 일괄 + 편별 조정) → **브랜드 정보 입력** →
(끝). 단계는 작업자가 밀고 컨펌은 클라이언트가 한다. `/admin/review` 는 검수 큐에서
**진행 현황**으로 바꿨다 — 지금 공이 누구에게 있는지 보고, 막힌 것만 손으로 뚫는 자리다.

### 그 밖에

- `inquiries` 9건의 담당자명이 `유건호` 로 들어가 있었다(내 발송 테스트 데이터) → `송건호` 로 수정.
  코드에는 없었고 DB와 내 메모리에만 있었다
- 작업자 화면의 "기획" 칸은 **작업 메모(선택)** 로 내렸다. 제출 조건이 아니다

### 추가 — 드라이브 직접 업로드 (같은 날)

작업자가 결과물 링크를 손으로 복붙하지 않는다. 끌어다 놓으면 지정 폴더로 바로 올라가고
파일명은 규칙대로 자동으로 붙는다.

**파일은 우리 서버를 지나지 않는다.** 서버는 구글에서 재개 가능 업로드 세션 URI 만 받아
브라우저에 넘기고, 바이트는 브라우저 → 구글로 직접 간다(XHR PUT, 진행률 표시).
영상 한 편이 수백 MB 라 서버를 통하면 Vercel 요청 본문 제한(100MB)에 먼저 걸린다.
세션을 열 때 `Origin` 헤더를 넣어야 구글이 CORS 헤더를 붙여 준다 — 빠뜨리면 브라우저가 PUT 을 막는다.

`googleapis` 패키지는 쓰지 않았다. 토큰 하나 받자고 의존성을 늘릴 이유가 없어서
`node:crypto` 로 RS256 JWT 를 직접 서명한다(`lib/google-drive.ts`, 약 40줄).

#### 파일명은 작업자가 짓지 않는다

`{앞자리}_{편번호}_{제목}_{형식}_{완성날짜}[_fin]`. 작업자는 제목과 형식(9x16/1x1/16x9)만
고르고 나머지는 조립된다. 손으로 붙이게 하면 폴더가 반드시 엉망이 된다.
수정 반영 단계(`revising`)에서 올리면 `_fin` 이 자동으로 붙는다.

**앞자리는 브랜드명이 아니라 별칭이다.** 규칙 자체는 브랜드명 자리지만 작업자에게
브랜드를 알려주지 않는 게 전제라 기본값이 `work_code`(W-0001)다. 브랜드명을 쓰고 싶으면
어드민에서 별칭에 적으면 된다 — 판단은 사람이 한다.

#### 어드민 화면을 한 자리로 모았다

### 소스 전달 = 작업 시계의 0시

누르면 ① 준비 트랙이 닫히고 ② **편마다 마감일이 박히고**(주 2편 기준 편당 7일 —
1·2편 D+7, 3·4편 D+14 …) ③ 배정된 작업자에게 시작 안내 메일이 나간다.

### 구글 드라이브 — 파일이 우리 서버를 지나지 않는다

서버는 구글에서 **재개 가능 업로드 세션 URI** 만 받아 브라우저에 넘기고, 바이트는
브라우저 → 구글로 직접 간다. 영상 한 편이 수백 MB 라 서버를 통하면 Vercel 요청 본문
제한(100MB)에 먼저 걸린다. `googleapis` 패키지는 쓰지 않았다 — `node:crypto` 로 RS256
JWT 를 40줄로 서명한다(`lib/google-drive.ts`).

**밟은 함정 세 개:**
- 서비스 계정은 **개인 드라이브에 파일을 소유할 수 없다**(저장용량 0). 반드시 공유 드라이브
- 세션 생성 때 `Origin` 헤더를 넣어야 구글이 CORS 헤더를 붙인다. 빠뜨리면 브라우저가 PUT 을 막는다
- 새 형식 Supabase 키(`sb_secret_…`)를 **Storage API 가 아직 안 받는다**("Invalid Compact JWS").
  버킷은 SQL(`insert into storage.buckets`)로 만들었다

폴더는 **프로젝트마다 따로** 판다 — `{공유 드라이브}/{브랜드명_플랜}/{소스, 완성본}`.
한 폴더를 여러 프로젝트가 같이 쓰면 브랜드가 섞인다. **공유 드라이브 멤버로는 아무도 추가하지
않는다**(멤버가 되면 드라이브 전체가 보인다). 폴더 단위 권한만 준다.

권한은 **한 종류다 — 참여자 전원이 두 폴더 다 편집자.** 역할별로 읽기/쓰기를 쪼개 봤지만
설명만 길어지고 실익이 없었다. 지워도 공유 드라이브 휴지통에 30일 남는다.
**작업자를 배정하면 폴더가 없을 때 알아서 만들고 권한까지 건다** — 버튼을 따로 누르지 않는다.

파일명은 작업자가 짓지 않는다: `{브랜드명}_#{편번호}_{컨텐츠명}_{완성날짜}_{v1|fin}`.
버전은 **둘뿐이다** — 중간 버전을 열어 두면 폴더에 v2·v3·진짜최종이 쌓인다.

### 자동 메일 7종 — 전부 우리가 보낸다

소스 전달 / 48시간 진행 확인 / 마감 24시간 전 / 1차 완성본 / 최종본 / 완료 통지 /
클라이언트 방치 리마인드. 시간 기반 3종은 cron 하나가 매일 **오전 10시(KST)** 에 돈다.
같은 메일은 한 번만 — 편에 발송 시각을 남긴다.

**조용시간: KST 20:00~10:00 발송 금지.** 그 시간에 생긴 알림은 버리지 않고 Resend
**예약 발송**(`scheduled_at`)으로 다음 오전 10시에 나간다. 우리 서버가 큐를 들고 있지 않아
배포가 재시작돼도 예약이 남는다. 이력에는 `scheduled` 로 적재된다.

⚠️ 조용시간이 **두 곳에 있다.** `lib/mail.ts`(모든 메일, 예약 방식)와
`lib/blog-schedule.ts`(blog 전용, 건너뛰기 방식). 다른 세션이 같은 요구를 따로 구현했다.
고장은 안 나지만 **발송 시간을 바꿀 땐 두 파일 다** 고쳐야 한다.

브랜드가 직접 지급하는 구조라 리워드가 보이지만 우리는 구조가 다르다.

**릴스/피드 스코어와 상위 % 는 만들지 않았다** — 그건 그 플랫폼이 자기 DB 로 계산한
자체 지표다. 우리에겐 모수가 없어서 만들면 지어낸 숫자가 된다.

### 브랜드 AI 세부분석 — 만들었다가 지웠다

작업자가 자료를 더 받도록 붙였는데 사장님 판단으로 걷어냈다. 작업자는 자기가 쓰던 AI 로

### 4. 지시문과 검사식이 서로 다른 말을 하고 있었다

첫 OpenAI 원고가 6개 항목에서 미달로 걸렸다. 원인은 모델이 아니었다.

| | 지시문 | 검사식 |
| --- | --- | --- |
| 본론 H2 | "블록 수 6~7개" (FLOW 7단계를 말한 것) | 3~5개 |
| 분량 | "3200자 **이상**" | 3200~4600자 |
| 시각 자료 | "4~5개" | `:::source` + 표 합산 5개 이내 |

게다가 자료 규격이 **섹션마다 최소 1건** 인용을 요구해서, 섹션이 5개면 인용만
5개라 표 하나만 넣어도 미달이다. 두 규칙이 동시에 성립하는 구간이 좁다.

(`sectionMax = min(f.maxH2, maxVisuals - f.minTables)`). 앞선 모델은 우연히
통과했을 뿐, 지시문이 처음부터 틀려 있었다. 고친 뒤 미달 6건 → 1건 → 교정 후 통과.

### 조판 규격과 넘침 검사기

사흘새 같은 사고가 세 번 났다 — 증빙 표가 `overflow:hidden` 에 잘리고, 표를
끼우니 영상 캡처가 깎이고, CSS 치환 실패를 확인 안 하고 "고쳤다"고 보고했다.
원인은 하나다. **`.page` 가 `overflow:hidden` 이라 넘쳐도 화면은 멀쩡해 보인다.**

- `docs/deck/LAYOUT.md` — 그리드(본문 밴드 123.5mm·12칼럼)와 장표 유형 10종
- `npm run deck:doctor` — 넘침·잘림·미로딩·빈칸을 숫자로 잡는다. 유형은

### 드라이브 영상 — "못 한다"고 단정했다가 뒤집힌 것

처음에 **MCP 로 영상을 못 받는다고 단정했다. 한 번도 시도하지 않고.**
실제로 해보니 하네스가 큰 결과를 파일로 떨어뜨려 10MB 이하는 받아진다.
다만 10MB 초과는 진짜로 막힌다(`over limit of 10 MB`).

그래서 rclone 을 붙였다(brew 없이 바이너리만 `~/bin`). 공유 드라이브 5개 폴더에
**영상 207편 / 8.0GB**. `(Footage)` 61편을 뺀 완성 소재 149편에서 브랜드 균형을
맞춰 38편을 골라 720p 로 변환했다. 총 60편.

⚠️ macOS 한글 파일명이 **NFD(자모 분리)** 라 슬러그화하면 한글이 통째로 날아간다.
39편 중 20편만 만들어지고 나머지는 이름이 겹쳤다. NFC 정규화 + 해시로 막았다.

목적 분류(인터뷰형·후기형·정보근거형…)는 **편당 4프레임을 뽑아 직접 보고** 매겼다.
파일명 추측이 아니고, 근거 자막을 `lib/clips.ts` 줄마다 적어 뒀다.
배치는 브랜드 라운드로빈 — 같은 화자가 나란히 오면 "그 업종 전문"으로 읽힌다.

### PDF 33.8MB → 10.1MB (Gmail 첨부 한도)

용량 문제가 아니라 **발송 실패 위험**이었다. Gmail 첨부 한도가 25MB 인데 base64 로

### 슈파베이스 전 표 권한 점검 (2026-08-20 마감)

36개 표를 익명 키와 `set role anon` 으로 전부 재봤다. 측정값만 적는다.

| 항목 | 결과 |
|---|---|
| RLS 꺼진 표 | **0개** |
| 익명이 읽을 수 있는 표 | `plans`(active=true) · `blog_post`(status=published) — 둘 다 공개가 맞음 |
| 익명이 **쓸 수** 있는 표 | **0개** (트랜잭션 안에서 실제 INSERT 시도 후 롤백해 확인) |
| 무조건 통과(`true`)하는 쓰기 정책 | 0건 |

`anon`/`authenticated` 에 INSERT·UPDATE·DELETE **GRANT 는 34개 표에 남아 있다.**
슈파베이스 기본값이다. 다만 쓰기 정책이 하나도 없어 RLS 가 전부 막는다 —
`inquiries` `orders` `plans` `spend_log` `profiles` 에 실제로 넣어 보고
다섯 건 모두 `row-level security` 로 거부되는 것을 확인했다.

즉 **GRANT 회수는 방어층을 한 겹 더 얹는 일이지 지금 뚫려 있는 구멍이 아니다.**
급하지 않다. 하게 되면 `revoke insert,update,delete,truncate on all tables
in schema public from anon, authenticated` 한 줄인데, 서버 코드가 전부
서비스 롤을 쓰는지 먼저 확인하고 돌려야 한다.

이날 실제로 막은 것은 `blog_post_week` · `blog_post_metric` 두 개다
(마이그레이션 `20260820000003`).
