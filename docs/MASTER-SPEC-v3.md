# PART A. 전략 & 서사

## A1. 핵심 서사 (모든 카피의 상위 원칙)

"싸고 빠른 제작 대행"이 아니라 **"하이엔드 전략 집단의 소재 시스템을 패키지 가격에 개방"**. 세 기둥:

1. **경험 기반 위너 숏폼** — 실제 성과(매출)로 검증된 경험을 바탕으로 매출 위너형 숏폼을 기획·납품
2. **업계 Top 바이럴 전문가 시스템** — 업계 최상위 바이럴 영상을 담당해 온 전문가들이 시스템으로 투입
3. **하이엔드 전략 집단의 개방** — 글로벌 대기업부터 스타트업까지, 평균 프로젝트 단가 2천만원 이상의 전략 집단(해그로시)이 숏폼 소재 영역만 합리적 가격으로 제공

가치 축: **최대한 효율적으로 · 고성과 목표로 · 합리적인 가격으로.**
톤: 조금 더 다르고, 특별하고, 사명감을 다하는 프로젝트 집단. 과장·호객 대신 절제된 확신 (hgrs.io "작품 빚듯" 결).

가격 명분 한 줄 (반복 사용):
> "월 1천만원 이상 용역으로만 진행되던 해그로시의 소재 시스템을, 숏폼 영역만 패키지로 열었습니다."

## A2. 상품 구조

- **플랜 1 — 풀 파이프라인**: 인플루언서 바이럴 시딩 + 확보 소스로 전환형 숏폼 제작 (A→B 연속)
- **플랜 2 — 전환 숏폼 단독**: 브랜드 보유 소스 제공 조건 (B만)
- 광고 운영은 상품화하지 않음 — FAQ에 "별도 협의" 한 줄만
- **가격**: 2026-08-10 확정. 판매가 한 값만 표기 (정가 취소선·할인율 배지 없음)
- **베타 이벤트 ② 헤드 전략 리뷰**: **스케일 티어(플랜1 인플30+숏폼20) 및 플랜2 20편 구매 한정** — 해그로시 헤드(대표)가 캠페인 구조와 브랜드 USP를 직접 리뷰하는 1회 세션 제공
  - 범위 명시: 60분 화상 세션 또는 서면 리뷰 1회. 캠페인 구조 진단 + USP·포지셔닝 피드백까지. 광고 운영·상시 자문은 범위 외
  - 표기: "베타 기간 한정" — 정식 전환 시 제외 가능한 퇴로 확보
  - 카피: "평균 단가 2천만원 프로젝트를 킥오프해 온 헤드가, 당신의 캠페인 구조를 직접 봅니다."

순서(2026-08-10 확정): **① 현장 사진 → ② 숫자 → ③ 역할표**

- **① 현장 사진이 첫 근거다.** 우리 사람이 장비를 들고 찍은 사진 8장을 섹션 상단에 모자이크로 크게 깐다(맨 앞 1장은 2×2). 앞 4장은 `loading="eager"` — lazy 로 두었더니 스크롤 도착 시점에 빈 회색 칸만 보여 "팀 사진이 없다"는 말을 들었다.
  - 이전에는 섹션 맨 아래 얇은 마퀴 띠였다. 장식으로 읽혀 근거 역할을 못 했다. 되돌리지 말 것.
- **② 숫자 3개**: 30+ 브랜드 프로젝트 / 역할 10 / 평균 프로젝트 단가 ₩2,000만+
  - "김포 촬영 오피스 1"은 철회. 상주 오피스가 없다.
- **③ 역할표 10칸**: 한 사람이 다 하는 게 아니라는 걸 눈으로 보여준다. `from`(출신)은 **문서로 확인된 것만** 적는다.

### S-Diagnosis. 플랜 진단 — Diagnosis (2026-08-10 신설)

Reviews ↔ Pricing 사이. **가격 허들을 낮추는 자리다.**
가격을 먼저 던지면 "숏폼 한 편에 얼마"라는 비교로 끌려간다. 그 앞에 진단을 세워
지금 어느 국면인지 짚어야 편수·구성이 근거를 갖는다. 질문 자체가 제안서다.

- **질문 5개 / 보기 3~4개.** 4개면 얕고 6개부터 이탈이 난다. 보기는 현재 상태를 있는 그대로 고르게 하고, 이상적인 답을 유도하지 않는다.
- 질문마다 **왜 묻는지 한 줄**을 붙인다. 이 한 줄이 전문성의 대부분이다.
  1. 타겟별 객단가와 USP가 정리돼 있나 (가이드라인 핏)
  2. 소재를 어떤 목적으로 쓸 계획인가 (브랜디드 ↔ 리얼리티 / 트래픽 ↔ 매출)
  3. 내부에 활용 가능한 소스가 있나 (리뷰 영상·내부 촬영본·룩북·누끼)
  4. 지금 광고 소재 상태 (고갈 / 판독 불가 / 미시작 / 정상)
  5. 월 필요 편수 (1 / 5 / 10+ / 모름)
- **결과 = 플랜 하나 지목.** 갈림길은 둘뿐이다. ① 소스 유무 → 싱글/패키지 ② 편수 → 티어.
  스케일(인플 30)은 자동 지목하지 않는다 — 그 규모는 상담에서 정한다.
- 결과 카드에 **답변에서 뽑은 근거 4줄**을 붙인다. 추천이 아니라 진단으로 읽혀야 한다.
- **결과에 금액을 적지 않는다.** 구성까지만 말하고 CTA 하나 — [이 구성으로 소개서 받기 → `#apply`].
  - "헤드 상담·문의" 같은 장치는 두지 않는다. 다음 행동은 신청 폼 하나뿐이다.
- 로직·문구 단일 출처: `lib/diagnosis.ts`

## E1. 브랜드 프로필 온보딩 (최초 1회 — ZET 패턴)

## E2. 진행 파이프라인 (상태 머신)

**2026-08-10 단계 어휘 확정.** 고객 화면에 그대로 노출되는 문구다. 내부 용어(waiting/reviewing/…)는 폐기했다.
단일 출처는 `lib/stages.ts`이며 DB check 제약과 1:1이다.

```
[인플루언서 시딩 · stage_a] 패키지 플랜 전용. 싱글 플랜은 null = "해당없음"
  guideline(컨텐츠 가이드라인 작업중) → recruiting(모집중) → confirmed(확정)
  → shipping(제품 및 서비스 배송중) → producing(컨텐츠 제작중) → live(채널 라이브 확인)

[숏폼 기획제작 · stage_b] 전 플랜 공통
  source(소스컷 확인중) → planning(기획중) → produced(제작완료)
  → revising(최종수정 반영중) → download(다운로드하기)
```

- 두 트랙은 화면에서 **나란히** 보인다. 싱글 플랜은 시딩 트랙 자리에 "해당없음"만 적는다.
- `download`에 도달하면 그 캠페인은 완료로 본다.
- 전이는 전부 admin 액션. 예외 2개만 brand 액션: ① 완성본 확인 [수정 요청 1회 | 최종 승인] ② 최종 확인 약관 동의→승인

### 인증 — 이메일 + 비밀번호 (2026-08-10 확정)

- **소셜 로그인 없음.** 회원 DB를 우리가 직접 들고 가야 이메일 마케팅·CRM이 가능하다. 가입 수단은 이메일 하나만 연다.
- 가입 입력: **이메일 · 비밀번호(8자+) · 회사명 · 담당자 이름 · 직책**. **도메인 제한은 두지 않는다** — gmail·naver로 실무를 보는 대표가 대부분이고, 도메인으로 거르면 그 사람들이 가입 자체를 못 한다(2026-08-10 철회).
- **이메일 인증이 먼저다.** ① 이메일 → 인증번호 발송 ② 6자리 확인 ③ 비밀번호·회사정보·동의 → [가입 완료]. 인증 시점에 계정이 먼저 생기므로 `profiles.signup_completed`로 반쪽 계정을 구분한다. 로그인은 이메일+비밀번호.
- 진입점은 요금표의 "이 플랜으로 시작하기" → `/checkout/<slug>`. 비로그인이면 `/signup?next=...`로 보내고, 인증이 끝나면 고르던 결제 화면으로 되돌린다.
- **동의 2종** — 전문을 가입 화면에 접어서 함께 띄운다(링크로 빼면 읽지 않는다). 전문 원본은 `lib/consents.ts`, 동의 이력은 `user_consents`(user_id·kind·version·agreed·시각·IP·UA).
  - `required` [필수] 이용약관 및 개인정보 수집·이용 동의 — 미동의 시 가입 불가
  - `marketing` [선택] 광고성 정보 수신 및 마케팅 활용 동의 — 정보통신망법 제50조. 미동의해도 이용 제한 없음
  - **전문을 고치면 `CONSENT_VERSION`을 올린다.** 버전을 그대로 두면 과거 동의가 새 문안에 동의한 것처럼 보여 증빙이 무너진다.
- Supabase 설정 의존: `mailer_otp_length=6`, magic link·confirm signup 템플릿에 `{{ .Token }}`(적용 완료). **내장 SMTP는 시간당 2건 제한** — 실사용 전 Resend SMTP 연결 필수(PART H).

## F4. 결제 (확정: 결제 시점 위젯)

- **카드 결제가 기본이다.** 그 외 수단(간편·가상계좌·빌링)은 앞 단계(가입→결제 진입)를 실제로 확인한 뒤 열지 결정한다.
- 플랜·수량 선택 → 주문 생성(pending) → **토스 결제위젯** 렌더(카드 우선) → 인증 리다이렉트 → `/api/payments/confirm`에서 시크릿 키 승인 → paid + `projects` 자동 생성 (+brand_profile 연결, head_review 티어면 `head_review_status='available'`)
- `/api/payments/webhook`: 가상계좌 입금 통지
- 주문요약 화면 체크박스 2개: A수정불가 정책 / 환불규정
- 세금계산서: 결제 폼에서 사업자번호·발행 이메일 수집 → 어드민 수동 발행 (자동화 Phase 2)
- 심사 요건: 푸터 사업자정보 완비 + 상품 페이지 + 환불규정. 카드사 심사 7~10일
- Phase 2: 빌링키 카드등록(토스 자동결제 별도 계약 — 조건 미확인, 영업 문의), 네이버페이(토스 위젯 간편결제 포함 여부 계약 시 확인)
